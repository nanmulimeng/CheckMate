# 备份与恢复

## 备份机制（自动）

- `/etc/crontab` 每天 **04:00**（服务器时区 Asia/Shanghai）调用 `/opt/checkmate/backup.sh`。
- 脚本内容见 `deploy/setup.sh` 第 5 步（由 setup 写入服务器），做的事：
  1. 用发布包自带的 better-sqlite3 对 `/var/lib/checkmate/prisma.db` 做**在线快照**
     （`db.backup()`，避免直接 tar 运行中的库文件拿到撕裂副本）；
  2. `tar czf` 打包 `photos/` 全目录 + 快照到 `/var/lib/checkmate/backups/checkmate-<日期>.tar.gz`；
  3. 只保留最近 **7 份**，更旧的删掉；
  4. 全程输出（含失败原因）追加到 `/var/lib/checkmate/backups/backup.log`。
- 健康自查：`tail /var/lib/checkmate/backups/backup.log` 应看到每天的 `backup done` 行；
  出现 `ERROR:` 行即该日备份失败（commonly：磁盘满、current 软链悬空）。

## 恢复步骤（服务器上操作）

前提：已 `ssh checkmate` 登录。

```bash
# 0. 停应用，避免恢复期间有写入
pm2 stop checkmate

# 1. 选一份备份（列表按时间倒序）
ls -t /var/lib/checkmate/backups/*.tar.gz

# 2. 解包到根（包内路径是 var/lib/checkmate/photos 与 var/lib/checkmate/backups/prisma-snapshot.db）
tar tzf /var/lib/checkmate/backups/checkmate-2026-09-01.tar.gz   # 先核对内容
tar xzf /var/lib/checkmate/backups/checkmate-2026-09-01.tar.gz -C /

# 3. 用快照覆盖正式库（快照是备份当时的完整库）
cp /var/lib/checkmate/backups/prisma-snapshot.db /var/lib/checkmate/prisma.db

# 4. 起应用并验证
pm2 start checkmate
pm2 logs checkmate --lines 20 --nostream   # 无报错即可
```

注意：

- 解包会把 `photos/` 整个替换成备份时点的内容（打包的是全量目录）；
  备份之后的**新照片**会丢——恢复是回到备份时点，不是合并。
- `prisma-snapshot.db` 会留在 backups 目录里被次日备份再次打包，
  属预期行为（覆盖写，不膨胀）。
- 恢复后 sessions 不受影响（cookie 密钥在 `/opt/checkmate/.env.production`，不在备份里也不需要）。
- 如果整个 `/opt/checkmate` 都没了（换机器/重装）：先跑 `deploy/setup.sh` 重建环境，
  再把备份包里的 `var/lib/checkmate/photos` 与快照库放回原位，最后 `deploy/deploy.sh` 发一个新版本。
