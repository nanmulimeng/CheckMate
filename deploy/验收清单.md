# 验收清单（部署前手动验收）

在本地 `pnpm dev` 起服务（http://localhost:3000），用两个浏览器（或普通+无痕窗口）模拟两个用户，按下表逐项走一遍。**全部通过后才进入真实服务器部署。**

每项都给出：点击路径 → 预期结果。任何一项不符，停下来修完再继续。

| # | 场景 | 点击路径 | 预期结果 |
|---|------|----------|----------|
| 1 | 邀请码注册 | 窗口 A 打开 `/register`；邀请码从 `dev.db` 的 `Setting.invite_code` 查（`sqlite3 dev.db "select value from Setting where key='invite_code'"`，或看 seed 日志脱敏前的库值） | 正确邀请码 → 注册成功并自动登录进 `/`；错误邀请码 → 红字「邀请码错误」 |
| 2 | 首用户是管理员 | 承接上一步，看窗口 A 的顶部导航 | 导航多出「管理」入口；`/admin` 能打开（第二个注册的用户没有该入口，访问 `/admin` 被弹回 `/`） |
| 3 | 全站导航 | 依次访问 `/`、`/me`、`/weekly`、`/settings`、`/admin` | 每页顶部都有同一套导航（首页/我的/周结算/设置[+管理]），右侧固定「打卡」按钮；页面原标题区在导航下方保留 |
| 4 | 打卡（不带照片） | 点导航「打卡」→ 选科目、时长 60、一句话总结 → 提交 | 跳回 `/`，今日动态出现这条打卡；「还没打卡」名单里自己消失 |
| 5 | 打卡（带照片） | 再点「打卡」（换一个科目）→ 添加照片（可连选 3 张，自动压缩）→ 提交 | 动态流卡片显示照片缩略图；超过 3 张会提示并忽略多余张数 |
| 6 | 01:00 锁定模拟 | 把系统时间调到次日 01:30（或临时改 `Setting.deadline_hour` 为「当前小时-1」后重启 dev）；回到 `/` 点「打卡」 | 记入日期只剩「今天」，昨天已不可选；直接 PATCH 昨天的打卡会 403「该打卡已锁定」（页面编辑入口消失即可） |
| 7 | 点赞评论 | 窗口 B 注册并登录后，在 `/` 对窗口 A 的打卡点赞、评论「卷死了」 | 点赞数 +1 可取消；评论即时出现，双方都能看到 |
| 8 | 催学（幂等） | 窗口 B 在「还没打卡」名单对窗口 A 点「催一下」；同一天再点一次 | 第一次成功推送（A 配了 SendKey 时收到微信消息，没配则服务端跳过）；第二次按钮提示今天已催过（接口 409 幂等） |
| 9 | 热力图 | 窗口 A 打开 `/me` | 近 26 周热力图上今天/昨天有色块；连续打卡、累计打卡、累计时长与实际操作数一致；按科目时长条形图包含第 4/5 步的科目 |
| 10 | 周结算 | 打开 `/weekly` | 默认展示最近一个完整周；缺卡最多的人置顶并带 👑 奶茶候选人徽标；「上一周/下一周」可翻；非法 `?week=` 值被弹回默认周 |
| 11 | 测试推送 | `/settings` → SendKey 填入 Server酱 SendKey → 保存 → 点「测试推送」 | 保存后状态变「已配置」；测试推送后微信收到标题「测试推送」正文「Server酱配置成功」；未配置时按钮禁用；留空保存 = 清除 |
| 12 | 改昵称 | `/settings` → 昵称改掉 → 保存 | 动态流/周结算/成员列表全部显示新昵称；超 20 字被拦 |
| 13 | 科目管理 | `/settings` → 新增「408 数据结构」；对「政治」改名；上移/下移调整顺序；尝试删除有打卡记录的科目 | 新增成功；重名 409「科目名已存在」；打卡页科目下拉顺序随排序变化；有历史的科目删除按钮禁用，悬停提示「该科目有历史打卡，不能删除（可改名）」；无历史科目可删 |
| 14 | 修改密码 | `/settings` → 旧密码/新密码（≥8 位）/确认 → 提交；退出后用新密码登录 | 正确旧密码 → 修改成功；错误旧密码 → 红字「旧密码不正确」（接口 403）；新密码不足 8 位被拦 |
| 15 | 管理员改全局设置 | 窗口 A（管理员）打开 `/admin` → 改考试日期为 `2026-12-19`、提醒小时 21、邀请码 → 保存 | 保存成功回显新值；`/` 顶部出现考试倒计时；填 `2026-13-01`/`2026-02-30`/`abc` 等垃圾日期被 400 拦截；提醒小时填 24 被拦 |
| 16 | 非管理员无权 | 窗口 B 直接 `curl -X PATCH localhost:3000/api/admin/settings -H 'Content-Type: application/json' -d '{"exam_date":"2026-01-01"}' --cookie '…窗口B的cookie…'`（或直开 `/admin`） | 接口 403；页面被重定向回 `/` |
| 17 | 重置密码 | 窗口 A 在 `/admin` 成员列表对窗口 B 点「重置密码」 | 弹出一次性 8 位临时码 +「请口头转告，成员登录后应尽快自行修改密码」；用临时码登录窗口 B 成功；临时码不会在任何页面再次出现 |
| 18 | 立即提醒 | 窗口 A 在 `/admin` 头部点「立即提醒」 | 按钮下方显示「已推送 N 条提醒」（N=配置了 SendKey 且今天未打卡的人数）；已打卡的人不收 |
| 19 | 手机布局 | 手机连同一 Wi-Fi 访问 `http://开发机IP:3000`（或 Chrome DevTools 切 iPhone 视口） | 页面单列自适应不横向滚动；导航可横滑、打卡按钮不被挤掉；打卡表单、照片九宫格、周结算表格、设置页表单均可正常点选提交 |
| 20 | cron 三件套（可选） | `curl "localhost:3000/api/cron/remind?secret=<cron_secret>&force=1"`；`/weekly` 同理；对 `/api/cron/cleanup` 先传错 secret 再传对的 | 错 secret → 401；对 secret → 返回 JSON（`{"sent":N}` / `{"deleted":N,"unlinked":N}`），cleanup 会把悬挂照片的磁盘文件一并删掉 |

> 服务器部署后（`deploy/setup.sh` + `deploy/deploy.sh`）：换 8080 端口把第 19 项再做一遍，另查 `pm2 logs seti` 无报错、`ls /var/lib/seti` 有 `prisma.db` 与 `photos/`。
